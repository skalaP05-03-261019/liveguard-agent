# Phase 2 팀 공유 자료 반영 · 2026-10-22

## 적용 기준

사용자가 팀원 공유 자료 2개와 채팅 요약에 대한 최신 결정을 전달했다. 원본은 로컬에서 보존하고, 공개 저장소에는 정리 문서와 SHA-256 식별 정보만 남긴다. 원본 PDF/HTML은 이 폴더에 재배포하지 않는다.

- [시장조사 원문 PDF · 3쪽](team-materials.md#market-research)
- [역할별 팀 작업 정리 HTML](team-materials.md#team-workboard)
- [공유 원문 식별·파일 해시](source-manifest.json)

이 기록은 공유 문서를 읽어 정리한 것이다. 경쟁사의 현재 가격·기능·한국어 지원 및 고객 수요를 독립적으로 검증한 시장조사 결과가 아니다. 팀 작업표의 추천 우선순위나 체크박스를 실제 담당자 확정·작업 완료로 해석하지 않는다.

## 1. 사용자 최신 결정 — 채팅 요약

**요약 기술은 구현하고, 어떤 역할이 사용할지는 추후 논의한다.** 스트리머가 사용할 수도, 시청자가 사용할 수도 있다.

따라서 이전 제안서·세원님 역할 문서의 다음 내용을 갱신했다.

| 이전 기술 | 최신 적용 |
|---|---|
| 입장한 시청자가 읽는 요약으로 고정 | 이용 역할·제공 시점·화면 위치 미정 |
| 핵심 연결 이후 조건부 착수 | 공통 요약 기능의 최소 동작 흐름 구현 진행, P1로 우선순위 조정·병행 |
| 입장 이벤트 중심 호출 | 메시지·시간 구간을 받는 역할 중립 모듈. 실제 자동/수동 호출 계약은 추후 |
| 역할에 따라 바로 입력 범위 확대 | 초기 MVP는 PUBLIC을 기본 범위로 하고 서버가 호출자 권한 검증. 비공개 범위 확장은 별도 합의 |

역할 중립은 무인증 공개 API를 의미하지 않는다. 요약 입력은 서버가 허용한 범위여야 하며, 출력에도 시간 구간·근거·생성 시각을 남긴다. 영상·음성을 읽은 방송 요약과 구분한다.

## 2. 팀 시장조사에서 가져올 내용

### 차별화 후보 — PDF 실제 1~2쪽

문서는 프로필 강도 선택·사람 검토·입장 요약·B2B 연결 자체만으로 차별성을 주장하기 어렵다고 평가한다. 그 대신 다음 두 가지를 제안한다.

1. 한국어 우회 혐오·변형 욕설의 탐지 품질
2. 고객사 운영정책 조항을 근거로 설명하는 조사 결과

이는 팀 자료의 분석과 제안이다. 경쟁사에 같은 기능이 없다고 확정된 사실로 인용하지 않는다. 정책 근거 카드의 기존 기반과 실제 고객사 문서 등록·승인·버전·색인 격리 기능의 신규 범위도 구분한다.

### 고객 가설 — PDF 실제 2쪽

자체 AI 관제팀이 없는 라이브 서비스·라이브커머스 솔루션을 고객 후보로 제안한다. 문서 자체도 해당 고객층의 악성 채팅 문제·도입 수요를 보여주는 통계나 사례가 부족하다고 명시한다.

따라서 설계서에서는 고객 가설로 표기하고, PM이 문제 근거·고객 인터뷰 또는 공개 사례를 보강할 항목으로 남긴다. 대형 플랫폼이 절대로 고객이 될 수 없다거나, 소개 자료에 없는 기능이 실제로 없다고 단정하지 않는다.

### 출처 한계 — PDF 실제 3쪽

- 일부 경쟁 서비스 정보는 제3자 자료·과거 기사에 기반한다.
- 라이브 채팅이 아닌 뉴스 댓글 분석을 그대로 일반화하지 않는다.
- 한국어 지원의 명시를 못 찾았다는 것과 미지원은 다르다.
- 기능·가격을 발표에 사용할 때는 공식 최신 출처 재확인이 필요하다.
- 자료에 기재된 시장 규모·수요 근거의 공백을 임의 수치로 채우지 않는다.

## 3. 팀 작업표와 기존 제안서의 상태 정리

| 항목 | 공유 자료의 상태 | 적용 방식 |
|---|---|---|
| AI 채팅 요약 | 개발 진행, 타깃·제공 시점 추후 결정 | 사용자 최신 결정으로 재확인. 공통 기술 구현 진행 |
| 커뮤니티 은어 | 조사 예정 | 수집·사용 조건, 출처·문맥·정제·개인정보 검토 후 사례화. 이미 수집·학습한 것으로 표시하지 않음 |
| 방송별 필터링 | 레벨형·항목형·자연어형 비교·협의 | 기존 완화/균형/엄격은 레벨형의 제안 예시. 최종 설정 방식으로 확정하지 않음 |
| B2B2C·외부 플랫폼 | 방향 검토 | 판매 대상·실제 사용자·결합 수준을 별도 합의. 현재 외부 플랫폼에 연동 완료된 것으로 설명하지 않음 |
| 후보 탐지·제재 흐름 | 협의·검증 필요 | PASS 이전 호출, 실패 처리, 노출·승인·제재 주체를 BE와 맞춤 |
| P0/P1·역할별 체크리스트 | 팀 검토용 추천안 | 역할 책임을 논의하는 기준으로 사용. 체크 상태는 실제 검증 근거가 아님 |

## 4. 태관·세원님 Agent 분담에 미치는 영향

- 태관: 후보 탐지·공통 데이터/평가·고객사 설정 기준 비교·BE/Gateway·통합 연결.
- 세원님: 문맥 조사·정책 근거·조사 결과 구성·조사 품질 평가·역할 중립 요약 모듈과 해당 평가.
- 두 사람: 후보/사건/조사 결과 계약, 요약 입력·권한·시간창·근거/오류 계약을 함께 합의.

공유 작업표의 RAG/Data·QA·BE·FE 역할과 두 사람의 내부 분담이 겹치는 부분은 담당자를 확인한다. 작업표에 이름이 없는데 임의로 팀원에게 일을 배정하거나 기존 담당 범위를 대체하지 않는다.

## 5. 다음 회의에서 정할 항목

1. 차별화 문장: 한국어 우회 혐오 대응과 고객사 정책 근거를 이번 MVP에서 어디까지 보여줄지.
2. 고객 가설과 문제 근거: 누가 구매·운영·이용하는지, 부족한 수요 증거는 누가 확인할지.
3. 설정 방식: 레벨·유형별 항목·자연어 중 이번 구현 범위와 공통 금지 정책 경계.
4. 요약 공통 계약: 입력 메시지·시간창·권한·출력·근거·오류·무효화. 사용 역할은 별도 미정으로 유지.
5. 구현·평가 담당: 은어 조사·라벨 검수·공통 확인셋·실제 연동·요약 UI 시연 담당을 확정.
