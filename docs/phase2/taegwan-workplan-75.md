요약 이용 역할과 제공 시점, 고객사 설정의 최종 형식은 계속 미정입니다. 세원님이 사용할 공통 사례·식별자·기대 후보·실패 목록을 공유하되 조사 판정 기대값을 후보 기대값으로 대체하지 않습니다.

## 이번 구현

`app.candidate_detection.compare`는 기존 후보 평가기의 결과 두 개를 **원본 평가 사례**와 대조해 비교합니다.

- dataset SHA·사례 ID/순서·기대값·실제 입력 SHA가 달라지면 거부.
- 선택 실험마다 TP/FP/TN/FN과 교집합 사례의 전후 결과를 나란히 기록.
- 정상 오탐 수정/신규 오탐, 후보 누락 수정/신규 누락의 ID 기록.
- 오류 발생/오류 회복/계속 오류는 별도로 기록하고, 성공 사례 교집합의 지표와 섞지 않음.
- 지역·집단·변형욕설·반박·일반단어·불명확 문맥 등 태그별 지표. 태그가 겹칠 수 있으므로 합산 금지.
- 비교 보고서에는 채팅·인용·이유·임의 오류 본문을 복사하지 않음. 사례 ID도 민감할 수 있으므로 로컬 보고서는 기본 0600 새 파일로 생성하며 덮어쓰지 않음.

후보 프롬프트에는 일반 단어 일부를 욕설로 해석하지 않는 지침과 상대를 향한 변형/영문 욕설을 조사 후보로 보는 설명을 추가했습니다. BE 확정 사전·정책·처벌을 바꾸지 않았습니다. 새 16개 사례와 기존 20개는 직접 작성한 **개발 진단**이고 팀 검수·독립 확인셋이 아닙니다.

## 실제 모델 관찰 · 개발 진단

기존 설정 `gpt-5.4-mini`, 같은 기존 20개(기대 후보10/정상10), 변경 전·후 각 1회입니다. 모델·입력은 같고 후보 프롬프트만 바꿨습니다. 통계적 인과 개선이나 Phase 1 대비 개선율을 주장하지 않습니다.

`P2-15`의 '시발점' 오탐이 이번 실행에서 사라졌습니다. `P2-01`이 불확실 신호에서 더 강한 신호로 관찰됐지만 모델 변동을 배제할 수 없습니다. 중간 기준의 누락 2개는 `P2-17`, `P2-18`의 대상/문맥 불명확 사례입니다. 불확실 신호까지 포함하면 후보10개를 모두 선택하지만 이는 **운영 정확도 100% 또는 자동 차단 가능**을 뜻하지 않습니다.

새 개발 회귀 16개(후보8/정상8)는 유효16/오류0. clear-only는 TP7/FP0/TN8/FN1, 나머지 두 기준은 TP8/FP0/TN8/FN0였습니다. '씨바', 상대를 향한 'fuck'과 정상 일반 단어를 포함하며, 튜닝 방향을 알고 작성한 사례이므로 독립 확인셋이라고 부르지 않습니다. 정확한 유형 대응과 조사 타당성은 별도로 검수합니다.

지연은 변경 전 p50 1187.04ms/p95 1793.15ms, 변경 후 p50 910.54ms/p95 1658.45ms, 새16개 p50 876.26ms/p95 2182.13ms였습니다. 모두 순차 모델 호출~검증 지연이며 실시간 채팅 부하·BE/FE 도달 지연이 아닙니다. 지침 추가로 입력 토큰은 기존20개 20,248→23,208로 늘었습니다. 지연 감소를 프롬프트 개선의 확정 효과로 해석하지 않습니다.

## 재현

```bash
uv run --locked python -m app.candidate_detection.compare \
  --before evidence/phase2/candidate-before-75.json \
  --after evidence/phase2/candidate-after-75.json \
  --cases tests/fixtures/phase2/authored-candidates-v1.json \
  --groups tests/fixtures/phase2/authored-candidate-groups-v1.json \
  --out local-data/candidate-comparison.json

uv run --locked python -m unittest discover -s tests -p test_candidate_comparison.py -v
```

이 비교 명령은 저장된 예측으로 지표를 재계산하며 모델을 다시 호출하지 않습니다. 실제 모델 재측정은 기존 후보 CLI의 명시적 `--live --limit`을 사용하고 새 출력 파일을 지정합니다. 프롬프트·모델·원본 입력 SHA와 오류/coverage를 함께 비교합니다. UnSmile 원본이나 고객사 사례를 공개 예제로 덮어쓰지 않습니다.

신규 비교 무결성/오류/공개 범위 검사 8개를 포함해, 격리 PostgreSQL/pgvector·TCP 활성화 전체 **352 tests PASS, skip 0**을 확인했습니다. 통제 검사와 실제 모델 호출의 소스 해시·범위는 [검증 기록](../../evidence/phase2/verification-75.json)에 구분했습니다.

## 다음 우선순위

1. **공통 사례 검수:** 개발 사례에서 정상 예외·불명확 대상의 기대 후보를 세원님/정책 담당과 검수. 개발/확인셋을 분리하고 유사 문장·출처 누출을 점검. 확인셋은 지침 튜닝에 사용하지 않음.
2. **UnSmile 로컬 선별:** 원본 출처/커밋/파일 SHA/분할/행 참조와 서비스 기대값을 별도 보관. 다중 레이블을 후보 신호·BE enum으로 자동 매핑하지 않음. 데이터 사용 조건을 확인한 범위에서 진행하고 원본·변형본·색인을 이 공개 repo에 게시하지 않음.
3. **세원 조사 연결:** 같은 후보 ID에 대해 후보 누락/오탐과 조사 판정/근거/적절한 보류를 별도 측정. #70 평가기를 중복 구현하지 않음.
4. **BE 계약 준비:** [후보 접수 협의안](candidate-ingress-proposal.md)의 호출 위치·고객사/방송 범위·HELD·중복·실패·TaskEnvelope를 합의한 뒤 어댑터 구현. 지금 독립 후보가 실제 채팅을 가리는 것으로 표현하지 않음.
5. **공동 데모:** 정상/명확 욕설/변형 욕설/욕설 없는 지역비하/대상 불명확/사람 거절/오판 복구를 시연. 성공만 아니라 누락과 UNKNOWN도 설명하고, 실배포·통제 시험을 구분.
