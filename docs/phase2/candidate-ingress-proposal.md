# BE 후보 접수 협의안 · 미확정

BE 담당자 구현에 대한 변경 요청을 확정한 문서가 아닙니다. Agent #64/#65 소비자 구현에서 확인한 연결 공백과 합의할 항목입니다. BE 코드와 OpenAPI는 수정하지 않았습니다.

## 현재 가능한 경로

Agent 후보 API는 신호/인용/선택 여부를 반환하고, 조사 초안 API는 **이미 BE에 존재하는 미확정 CONTEXT_REVIEW·HELD 사건**을 조회해 조사합니다. 최신 BE OpenAPI에는 새 의미 후보를 접수해 이 사건으로 전환하는 경로가 없습니다. 따라서 PASS 채팅에 신호가 잡혀도 현재 새 API만으로 메시지가 가려지거나 운영자 카드가 생성되지 않습니다.

## 합의할 최소 항목

| 항목 | Agent 제안 / 확인할 내용 |
|---|---|
| 호출 지점 | 기존 채팅 저장/BE 필터와 후보 API의 호출 순서. 일반 채팅을 모델 지연 동안 대기시킬지 여부 |
| 권한 | BE가 메시지·방송·작성자·고객사 범위를 검증. Agent requestId/liveId만으로 권한 추정 금지 |
| 입력 정본 | 원문과 마스킹본 중 모델에 넘길 범위. 조사 단계는 BE 동결 snapshot 정본 사용 |
| 후보 내용 | requestId, messageId/liveId, 후보 신호·인용, 실험/프로필 식별·버전, 호출 결과·오류. 신호를 위반 enum으로 자동 치환하지 않음 |
| 프로필 소유권 | 고객사 설정은 BE 승인본·버전을 사용. 현재 clear-only 등은 실험값이며 운영 정책 아님 |
| 가시성 | BE가 HELD 전환·사유·대상 버전을 원자적으로 관리. 기존 RULE_CONFIRMED/HIDDEN/다른 hold 원인을 덮거나 해제하지 않음 |
| 사건·중복 | 동일 메시지 재전달, 기존 열린 사건/진행 중 검토와의 결합 여부, 멱등 키·상태 충돌·같은 입력 재호출 기준 |
| 증거 준비 | TaskEnvelope(caseId/snapshotId/expectedEvidenceVersion/threadId/traceId)는 BE 발행. 사건/문맥이 준비되기 전에 Agent 조사 시작 금지 |
| 실패·과부하 | 모델 오류·시간 초과·429·선택되지 않음·새 유형 정책 부재를 구분. 실패를 정상 판정이나 자동 공개 승인으로 치환하지 않음 |
| 방송 종료·취소 | 종료된 방송의 신규 사건/초안 수락 여부와 진행 작업 무효화. 운영자 결정은 실제 BE 상태 재검증 |
| 알림 | HELD 전환/사건/검토/결정의 기존 SSE·Outbox 및 작성자 전용 안내 유지 |

정확한 접수 API 경로, 동기/비동기 형식, 신규 상태/enum은 아직 정하지 않았습니다. 합의 전에는 Agent의 초안 출력으로 기존 판정 제출 API를 호출하거나 업무 DB를 직접 변경하지 않습니다.

## Phase 1 확인 중 발견한 별도 보완점

Phase 1의 실제 강퇴까지 흐름은 이전 통합 테스트에서 확인했습니다. 최신 FE `LiveConsole.vue`는 운영자에게 AI 근거/정책/결정 사유를 표시하지만, 시청자 LIVE_ACCESS_BLOCKED 알림은 일반 제한 안내입니다. 시청자 본인이 **어떤 확정 사건 때문에, 누구의 결정으로, 언제까지 제한되는지** 확인할 수 있는 최소 공개 정보는 BE/FE 담당자와 별도로 합의해야 합니다. 타인의 원문·개인정보·운영자 전용 메모를 그대로 공개하면 안 됩니다. Agent는 조사를 제공하고 최종 공개·접근 권한은 BE가 결정합니다.

또한 Agent 공유 Inbox Worker/lease #60은 iihlolo 담당 open 상태입니다. 단일 프로세스 통합 성공과 다중 Worker/장애 복구 완료는 구분합니다.
