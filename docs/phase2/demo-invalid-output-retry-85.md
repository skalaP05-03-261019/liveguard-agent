# 로컬 채팅 데모의 판독 실패 처리 (#85)

화면의 `판독 실패`와 `AI 근거 형식을 확인할 수 없습니다`는 채팅이 정책 위반으로 확정되거나 이용자가 제재되었다는 뜻이 아니다. Agent가 모델의 판독 결과 또는 원문 인용 근거를 검증한 뒤 유효한 결과를 받지 못해 해당 요청을 실패로 처리한 것이다. 실패한 메시지는 다음 판독의 문맥에 추가되지 않는다.

이전에는 `INVALID_MODEL_OUTPUT` 한 번으로 HTTP 502를 반환했다. 이제 로컬 데모의 `/api/screen`에서만 **같은 입력·문맥·추적 ID로 한 번 재시도**한다. 두 번째 결과에도 기존 근거 검증을 적용하며, 다시 실패하면 502와 `MODEL_RESPONSE_REJECTED`를 반환한다. 모델 인증 오류, 호출 시간 초과, 다른 도구 오류는 재시도하지 않는다. 두 번째 호출에서 결과가 달라질 수 있으므로 판독을 만들어 내거나 첫 실패의 근거를 채택하지 않는다. BE 사건·정책 판정·운영자 승인·집행에는 변경이 없다.

실제 모델에 앞선 채팅과 반복 표현을 담아 총 20회 재전송했으나 모두 정상 응답하여, 화면에서 발생한 **구체적인 형식 위반 필드**는 확인하지 못했다. 모델 원문을 로그나 외부 응답에 노출하지 않는 기존 제한은 유지한다. 합성 오류를 주입한 ASGI 회귀 검사는 첫 실패 후 복구, 두 번 연속 실패, 인증 오류의 재시도 제외를 확인한다. 전체 격리 PostgreSQL·ASGI/TCP 회귀 검사 385개가 통과했고, 실제 브라우저에서 정상 채팅·후보 채팅·문맥 전달과 페이지 오류 0개를 확인했다.

같은 안내가 계속 뜨면 화면의 **대화 초기화** 후 다시 보내거나, 서버의 모델 설정·가용성을 확인한다. 이 로컬 데모는 후보 신호를 보여주는 도구이며 최종 위반 판단은 기존 운영자 흐름에 따른다.
