# 정책 v3.2 Agent 전환 검토안 (#105)

정책·QA 담당의 조항 원문 확정 전에는 이 브랜치를 병합하거나 v3.2를 활성화하지 않는다. 이 문서와 `policy-v3.2.md`는 합의를 위한 구현 초안이다. 현재 운영 계약은 v3.1이다.

## 결정 방향

- 신규 `HATE` enum 없이 식별 가능한 집단의 열등 단정·배제 표현을 기존 `HARASSMENT`의 새 조항 CP-3.3으로 조사한다. 조항 ID는 정책·BE 담당이 최종 확인한다.
- CP-2.2는 자조, 비판·제지 목적의 최소 인용, 가벼운 고정관념 등 정상 예외를 다룬다. 대상이나 핵심 문맥이 불명확하면 보류한다.
- CP-6.1은 CP-3.3에도 해당하지 않는 정의 밖 위험에만 적용한다. 위협·성적 위해를 괴롭힘으로 억지 분류하지 않는다.
- UnSmile 점수는 후보 신호다. Agent는 같은 버전 정책의 원문과 앞뒤 문맥을 조사해 제안만 제출한다. HELD·운영자 결정·제재 계산은 기존 BE 책임을 유지한다.

## 버전과 배포

1. 정책·QA: CP-3.3과 CP-6.1의 문구·보호 범위·정상 예외, 검수 정답을 확정한다.
2. BE: OpenAPI 정책 버전, 허용 정책 ID, 사건/결정 검증, 후보 사전의 범위를 v3.2에 맞춘다. 기존 필터가 잡지 않은 PASS 메시지는 Agent에 오지 않는다.
3. RAG: v3.2를 별도 색인하고 CP-3.3 검색 근거와 Resource 일치를 확인한다. v3.1 색인은 이전 사건용으로 남긴다.
4. Agent/BE/RAG의 활성 버전을 같은 값으로 전환한 뒤 HELD 사건 → 정책 조사 → 운영자 결정까지 통합 검증한다. BE 준비 전에는 v3.1을 유지한다.

v3.1 사건은 v3.1 원문과 조사 지침을 사용하며 CP-3.3을 소급하지 않는다. v3.2 사건에는 v3.2 지침을 사용하고 판정 제출 시 사건의 `policyVersion`을 그대로 보낸다. 판정 제안만으로 숨김이나 강퇴가 확정되지 않는다.

## 검증 범위

- Agent 회귀: 두 정책 버전의 조사 지침 분리, CP-3.3의 `HARASSMENT` 검색 필터, 판정 요청의 버전 보존, 알 수 없는 버전 거부.
- 정책 검색: v3.2 질의셋의 CP-3.3·CP-2.2·CP-6.1 구분. 평가셋은 검색 검증용 초안이며 분류 성능 수치가 아니다.
- 조사 품질: 세원님 #88의 검수셋에서 집단 비하·자조·인용·대상 불명 사례를 v3.2 정답으로 별도 검수한다. 기존 v3.1 기대값은 수정하지 않는다.
- 실서비스 연결: BE 후보 사전, 버전 계약, 운영자 카드와 결정 API가 준비된 뒤에만 E2E를 통과했다고 기록한다.
